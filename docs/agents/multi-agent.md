# Multi-agent coordination

## 入口和模型

用户只与主代理交谈。主代理主动选择可独立委派的工作、协调依赖并验收；临时子代理只执行被分配的角色。能力、模型和思考强度由当前运行环境与用户指令决定，项目默认值见 [.codex/config.toml](../../.codex/config.toml)。

本项目所有子代理默认 `gpt-6.1-sol` / `high`，新上下文。使用当前 collaboration 接口时显式传入 `model="gpt-6.1-sol"`、`reasoning_effort="high"`、`fork_turns="none"`；后续转派也沿用该默认值。用户明确指定本次例外时按其要求执行。

客户端支持原生自定义角色时，选择下列 TOML 的 `name`。接口没有角色选择器时，先读取相应文件，把 `developer_instructions` 纳入派工正文，并显式传入上述模型参数；文件存在不等于已经派工。

## 角色和写入归属

- [ling_researcher](../../.codex/agents/ling_researcher.toml)：查现有代码路径或外部一手资料；对应用和配置只读，研究笔记仅写统筹明确分配的位置。
- [ling_planner](../../.codex/agents/ling_planner.toml)：综合规格、纵向切片、阻塞关系和验收；返回草案，由统筹负责对外记录。
- [ling_implementer](../../.codex/agents/ling_implementer.toml)：在指定目录／工作树内实现一项可验收结果并验证；只写获派范围。
- [ling_merger](../../.codex/agents/ling_merger.toml)：独占集成分支的写入，串行合入已验收成果并验证冲突解决。
- [ling_standards_reviewer](../../.codex/agents/ling_standards_reviewer.toml)：对固定版本做只读规范审查，以项目适用规则为依据。
- [ling_spec_reviewer](../../.codex/agents/ling_spec_reviewer.toml)：对同一固定版本做只读规格审查，以用户要求和验收为依据。

“只读”是派工职责；各子代理继承父会话的实际工具权限。除非任务明确要求，子代理把进一步拆分建议交回统筹，不自行扩大代理树或用户任务范围。

并行上限受运行环境约束；项目默认最多同时开启 3 个子代理。独立调查和双轴审查可以并行；有依赖的实施按任务图前沿推进。同一个工作目录、集成分支、共享计划或工单由一位指定负责人写入。统筹拥有任务图和对外更新。

## 最小派工包

每次实际调用提供：

- 本次目标与可以核验的完成条件。
- 角色说明、模型参数、实际工作目录／工作树、分支和固定基线。
- 允许写入的文件或目录、其他人的写入归属。
- 需求、工单、相关指令、源码或研究笔记的精确指针。
- 需要运行的检查或应验证的行为，以及当前已知限制。

只传当前子任务所需上下文，避免复制整段聊天。沿用已确认决定；授权或关键业务信息确实缺失时，把问题交回统筹，由统筹统一向用户处理。

## 返回给统筹

每位子代理汇报目标是否完成、证据及其适用范围，并提供：

- 实际修改文件与位置；没有修改也应明确。
- 工作目录、分支、基线／候选提交；未提交时明确标注。
- 实际运行的检查及结果，失败、跳过与环境限制分开记录。
- 剩余问题、依赖和需要统筹决定的事项。

审查意见另给规则或验收依据、具体位置、可触发情形与用户影响；不把推测当作已复现错误。统筹检查实物和验证结果后再认定完成，遇到失败先处理原因而非空转重派。

## 运行时核验边界

项目配置按 [OpenAI 子代理文档](https://learn.chatgpt.com/docs/agent-configuration/subagents) 使用原生默认值和独立 TOML 角色。新文件需要由客户端发现；当前会话同时依靠根指令与显式派工参数执行。分别记录配置解析、技能发现、实际派工及工程交付的验证结果，不以其中一种代替其余结果。
