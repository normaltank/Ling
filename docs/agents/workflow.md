# Engineering workflow

本项目采用 Matt Pocock 的问题澄清、行为规格、tracer-bullet 纵向切片、任务图前沿、先验证再实现和独立双轴审查方法。主代理负责统筹；用户直接交代目标即可。派工规则见 [multi-agent.md](multi-agent.md)。

## 先确定本次范围

1. 读取当前请求、适用指令、实际 Git 根目录、分支及未提交改动。任务涉及源码时，确认源码确实属于当前工作区与发布目标。
2. 查本次相关工单、词汇表和 ADR；保留其他任务的未提交内容。已有确认继续有效，旧计划不会自行恢复为当前任务。
3. 用用户可观察的结果界定验收点，选择下列最小充分路线。

## 按规模选路线

- **文档或配置小改动**：统筹直接修改，做格式、引用、原生解析等适当检查；存在真实不确定性时委派只读核查。无需为此制造完整任务图和多个工作树。
- **单个可验收行为**：先复现问题或确定验收行为，交一个实施者完成；有行为变更时按约定接口验证，再进行适当的独立审查。
- **多个可独立交付结果**：确定规格、划分纵向切片、建立真实依赖；各实施者独立工作，单一集成者串行合入；最后对固定版本做规格和规范两类独立审查。

## 阶段与完成依据

### 1. 澄清和探索

统筹先自行查可获得的代码、工单和文档。研究者调查确实未知的外部事实，规划者梳理行为及依赖。涉及领域概念时遵循 [domain.md](domain.md)。完成依据是：问题、目标、限制和仍需用户决定的业务问题均可具体说明。

### 2. 规格

把现有对话综合为问题、解决后的行为、必要用户故事、实现边界、测试接口、验收条件和范围外事项。优先在现有公共接口检验外部行为。只把真正未决且影响结果的选择交给用户；已经授权的目标不再重复确认。

完成依据：实施者可据此实现并验收，不必猜测重要产品行为。持续跨会话或多人协作的工程工作使用 [Issue tracker](issue-tracker.md) 保存规格；短小改动直接在当前任务记录即可。

### 3. 切片和任务图

每个切片交付一条可以演示或验证的完整路径，跨越实现它需要的各层；不要只按“数据库／接口／界面”拆任务。切片应适合一个新上下文。必要的预备重构先做；无法独立保持可用的广泛迁移采用 expand–migrate–contract。

记录真实阻塞边和验收条件，只从“阻塞项已满足且尚未认领”的前沿派工。工单使用真实编号建立父子和依赖关系；分流语义见 [triage-labels.md](triage-labels.md)。完成依据：每项的验收、依赖和写入归属明确，统筹可判断何时启动。

### 4. 实施和集成

给每位实施者发送目标、验收、上下文指针、工作目录、写入范围、基线和验证要求。行为变更在可用接口执行 red–green–refactor：先看到有意义的失败，再实现通过，最后整理。纯文档配置采用对应格式与实际解析检查。

有多个并行写入者时，每人使用隔离工作树和分支，基于当前集成版本。仅使用可用的原生工作树工具创建和归档；同一目录同时只允许一个写入者。实际源码未纳入本仓库时，先确定源码自身的可用隔离方式，不能以公开配置仓库代替它的版本基线。

实施者完成后由一个集成者串行合入，解决冲突并检查集成结果；新前沿解锁后继续派工。依赖失败时修复依赖或更新任务图。完成依据：所有验收行为在集成版本中成立，并有实际验证记录。

### 5. 独立审查和修复

对同一个固定基线与候选版本，分别安排规范审查和规格审查。规范审查依据真实项目约定；规格审查依据原始需求与验收。审查者只读，返回具体证据和影响。由实施者修复有效问题，重跑受影响检查；最终验证必须覆盖交付版本。

完成依据：有效问题已解决，剩余限制和未验证事项明确。用测试替身或小型派工演练得到的结果，分别标明其适用范围。

### 6. 交付

统筹核对结果、实际改动、验证证据和剩余事项，明确本地、提交、推送、PR、合并及部署各自状态。需要 PR 时先形成可审查的提交；远端发布沿用当前任务授权。只有真正完成相应验收才关闭工单；有 PR 验收约定时遵循该约定。归档不再使用的任务工作树，保留必要成果与交接指针。

## Matt 技能的调用边界

本页是本项目可自动执行的阶段适配，参考 `to-spec`、`to-tickets`、`implement`、`implement-spec` 的方法。安装在用户目录中的部分技能带有 `disable-model-invocation: true`；自动统筹执行这里的项目流程，不隐式调用这些技能，也不修改全局调用策略。用户显式调用时，以该技能的实际要求为准。

可自动选择且适用于当前任务的技能按需读取，例如 `diagnosing-bugs`、`domain-modeling`、`tdd`、`code-review`、`pr`、`research`。跨多会话、且路径尚不清晰的大型工作可在用户显式调用 `wayfinder` 时进入其决策地图流程；一般工程任务无需先建立地图。
